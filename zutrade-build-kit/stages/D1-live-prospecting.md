# 阶段 D1 真实寻找海外公司

只执行 D1。目标是从真实公开目录或搜索 API 发现海外企业，并保存足以复核的来源。当前 AI 仍为 mock，消息仍为 simulation。先阅读 PROSPECTING_SPEC 和 DATABASE_NOTES。

## 建设任务

1. 通过增量迁移加入 prospecting_runs，以及 leads 的研究任务/候选关联字段。保留 42 表基线，迁移后预期 43 张业务表。研究任务有真实状态、错误、执行版本、幂等身份和有界候选快照。
2. 建立 ResearchProvider 契约及两个明确入口：公开企业目录发现；配置搜索 API 后的关键词发现。前者真正从公开目录页面提取企业链接并追踪来源；后者实现 Brave Search 适配，只有账号与留存条件满足时启用。
3. 搜索条件包含代表工厂/产品、国家或地区、买家类型、关键词、排除条件和数量上限。工厂必选；研究不能直接生成无归属的销售线索。
4. 请求通过 worker 执行并写入研究任务状态。任务中途失败仍保留已成功结果与失败原因；重放/重试不无限抓取或重复导入。首次开始时间、固定截止时间、累计请求量与检查点持久化到 run；每次外部请求前原子占用预算，重试和重启不能重置。终态任务冻结证据，用户再次研究创建新 run。
5. 实现受控网页获取与静态 HTML/结构化数据提取。搜索摘要、目录证据、实际读取官网和人工确认分别显示；没有读取成功就不能显示官网已核实。
6. 采用确定性匹配规则：地理证据、业务类型关键词、产品用途、排除词；输出证据对应的理由和规则版本。匹配得分表示规则符合度，不是采购概率。未知字段保持未知。
7. 展示候选列表与来源抽屉、重复识别、保留/排除/重新研究操作。不可变 results_snapshot 与独立可变 review_decisions 分开，审核决定有原因、操作者、时间、版本/CAS 和审计，不能修改证据快照来保存排除标记。逐项确认身份后创建或关联 buyer，再创建 lead；导入检查当前决定，不能导入已排除项。公开邮箱不自动成为允许营销或已核实的 contact point。
8. 同域名候选提示可能重复；规范化不丢掉路径证据，不按公司名模糊合并不同实体。导入使用候选键和请求幂等身份。
9. 前端区分“来自真实网络”“离线测试数据”“摘要待复核”“访问受限”，显示实际抓取时间。搜索条件与错误可追踪，刷新后不丢失。

## 必须验证

- SSRF 的协议、IPv4/IPv6、私网/本机/链路本地地址、DNS 重绑定与重定向测试；响应大小、压缩后大小、超时、MIME 与请求量限制。
- worker 重试与取消有界，凭据不出现在响应、日志或前端 bundle。
- 中途终止 worker 后恢复，继续使用同一 run 的原截止时间和累计请求预算，不能获得新一轮免费预算；过期终态结果不能继续写入。
- 两次导入同一任务候选只创建一次销售线索；不同研究任务再次发现已有公司时提示已有记录。
- 研究范围与候选导入受 workspace、工厂和成员权限约束；研究快照不能进入工厂 facts。
- 离线 fixture 测试和真实联网测试分别执行、分别报告。

## 真实联网验收门槛

至少完成两次不同条件或不同公开目录的真实研究任务，从真实响应中发现多个不同公司候选，并抽查至少三个不同候选的来源；如果来源本身返回不足，报告实际结果并补充一次有界的合适来源验证，不能造数。

至少一条路径必须完整通过：真实公开目录发现→官网/来源复查→候选确认→lead 落库，或真实搜索 API→来源复查→候选确认→lead 落库。目录模式必须发现此前未预置的企业链接，不能拿固定公司名单做读网页演示。

若搜索 API 未配置，可完成公开目录模式并明确关键词搜索未启用。若所有真实路径都受环境阻塞，保持 verification_blocked；先完成本阶段可独立实现的代码与测试，再报告具体所需条件，不能退回模拟名单后标为完成。

## 人工验收路径

选择模拟 CT-01 工厂与“新加坡活动公司/礼品代理”等目标，使用一个实际可读的公开企业目录或配置好的关键词搜索，查看真实候选与时间。打开来源核对公司名称、业务和联系方式出处；确认一条候选成为线索，再次导入验证去重。

## 交付与停点

报告真实使用的 provider、公开来源、执行时间、结果数、错误和抽查情况，以及尚未配置的入口。不得宣称已找到可立即联系的合格买家。完成后停止，等待用户验收，不进入 D2。
