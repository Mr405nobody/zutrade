# ZuTrade 本地操作手册

2026-10-30。四入口是消息、找客户、产品、待办。消息和 AI 为模拟；真实企业研究的实现已有，但本机真实联网验收仍受阻。V 的公司样例明确为离线测试数据，不表示真实获客或真实询盘。工厂负责签约、收款及履约。

## 启动、账号与身份

在工程根目录执行 `./scripts/zu infra:up`、`./scripts/zu dev`，打开 http://127.0.0.1:5173 。日常环境已有数据，不重复 seed。`./scripts/zu db:accounts` 只输出私有账号文件位置，在本机打开取得密码，不复制到截图/报告。日常 Alex 沿用 B 账号；V 独立样例为 http://127.0.0.1:5673 ，停止后 `./scripts/zu ui:v`，账号在 `.local/v-test-last.json` 的 users.owner/users.sales。

owner 可看全部授权工厂、分配未归属会话、管理成员；sales 只能读获授权工厂。完整会话关联多个工厂时必须全部可见。当前指定且有效的 owner 才能批准商业外发；同为 owner 但未指定也不能批准。用户开发阶段验收不会代替系统内业务批准。

## 消息：先处理买家内容，再处理内部工作

会话列表显示各成员独立未读；打开会话会保存自己的已读位置。较早会话/消息可加载更多。模拟买家消息由 owner 的注入入口创建原始收据，再由实际 worker 标准化。重复同事件不会重复消息；失败收据在待办检查，未处理前会阻挡相关外发。

“内部工作区 · 仅团队可见”中的备注、AI建议、采购需求、报价及跟进草稿均为内部资料。买家消息区只展示实际标准化入站和统一网关模拟完成的出站，不会把内部备注当作买家收到的消息。

接管后旧自动 FAQ/跟进停止，有权成员仍可核对最新上下文，发起新的人工模板回复或提交商业审批。暂停新外发另外阻止全部新动作。上下文冲突提示出现时先刷新、核对最新消息，再明确确认；不要反复提交旧页面。

## 产品：确认供给事实

选择精确 SKU CT-01，展开来源与价阶。检查工厂、来源版本、摘要/定位片段、确认人、有效期及 buyer_visible 披露范围。上传文件只是资料，不代表事实已确认；owner 发布的有效事实才可用于报价和受控 FAQ。网上找到的买家研究不能当作工厂价格或交期依据。

示例规格为12oz、35×40cm、本色、单色单面logo；数量500—999件单价USD2.40，设置费USD30。500件合计USD1,230；800件USD1,950。价阶之外需工厂另行确认。20个工作日从图稿/样品及订金确认等约定条件起算，不等于六周到货。运费、税费、样品费用未提供时保持排除/待确认。

## 模拟 AI、需求与报价审批

在消息内部选择产品/商机及任务，点击“生成模拟建议”。“适用场景与固定业务时钟”列出支持的英文表达，完整目录见 build/E_SCENARIOS.md。相同输入可重放；未知表达和折扣/六周到货保证转人工，不是通用大模型。来源与输出校验可展开查看。

采用数量建议只保存需求，销售仍需确认工厂、产品、数量、规格和未决条件。修改建议保存内部草稿，拒绝保留历史。跟进建议采用时必须另选未来本地时间与 IANA 时区；场景固定日期不能自动拿来排程。受控材质/尺寸 FAQ 必须先由指定 owner 审核模板和允许值，再经统一网关；普通自由文本不走免审发送。

在“采购需求与内部报价”保存需求后生成确定性报价，核对金额、卖方、收件人、条件与排除项，生成并查看已保存 PDF。最终英文正文及 PDF 在提交前确定。“准备最终内容并提交审批”建立冻结快照；sales 没有批准按钮。owner 在会话内部或待办打开“最终外发内容预览”，逐项核对收件人、模拟账号、正文、报价版本及附件，再批准或拒绝。排队不是执行完成，以实际“模拟执行完成”为准；不代表真实 delivered/read。

数量、正文、收件人、账号、附件或商业条件改变后必须建立新版本并重审。旧报价/PDF/审批保留，失效原因可查。历史附件仍可授权读取，不代表旧报价仍可发送。日常 Alex 原 v17/500件/USD1230/PDF/pending 审批应保留；需要试批准时使用 V 隔离样例。

## 找客户：来源、身份和联系资格分别核对

选择代表工厂、产品、公开目录及条件后创建研究，worker 有请求次数、体积和时间预算。关键词目录筛选不等于全网搜索；Brave Search 未配置，不需要为当前任务购买。失败显示真实原因，不自动填公司。

打开候选来源查看实际获取时间、目录/官网证据等级、摘录、字段依据和匹配理由；保留或排除需填写原因，确认公司身份后导入。重复导入同一候选返回同一lead，新的研究保留旧来源。公开邮箱不等于许可；未知个人、邮箱和采购意向保持未知。离线样例不能通过虚构链接核对成为真实公司。

为已确认线索建立“内部演示身份（非真实联系人）”须指定 owner 明确授权，资格仅适用于 simulation。选择少量名单、逐人最终正文、账号、报价/PDF、时间、时区、节奏及截止后保存批次，再提交完整冻结版本审批。owner 查看完整名单和逐人内容再批准；成功、失败、延迟按实际单项结果显示。名单或内容变化必须新版本重审。手机以查看和紧急审批为主，复杂批次编辑用桌面。

## 待办、跟进与 unknown

待办聚合审批、联系方式核对、提醒、入站失败、发送失败/阻挡与unknown；可打开关联会话。默认跟进只是有负责人、目标、内部草稿、未来时间和时区的人工提醒，不自动外发。自动模拟跟进须预先冻结正文与收件人、由 owner 单独批准。

改期/改内容产生新业务版本，旧job重放不能执行新计划。新回复、接管、暂停、退订、需求/报价/事实/权限变化会在执行检查时停止旧计划，保留原因与历史。早到的任务不会提前到期。停worker再启动会从持久队列恢复，不能靠取消队列任务代替业务检查。

claimed 事务提交是撤销截止点。此前撤销会阻止发送；此后界面只能说取消申请或核对中，不能承诺本次已撤回。接受后丢响应可能进入unknown，在请求区“核对渠道接收记录”读取独立模拟账本。查不到仍不能证明未发送；无服务方幂等能力时不要盲目重发。停止后续尝试也应保留先前未知结果。

## 故障与保存

实时连接断开会明确提示，恢复后从数据库补查。401重新登录；403/404核对当前成员与完整工厂权限；409刷新版本；503检查API、数据库和worker。私有PDF缺失/摘要不符不能替换旧文件冒充成功。保留数据重启与独立恢复流程见 README 和 build/HANDOFF.md，禁止reset、schema push、删卷或重新seed来掩盖丢失。
